    - 400 `{"type":"error","error":{"type":"invalid_request_error","message":"Your credit balance is too low to access the Anthropic API..."}}` → exhausted
    - 402 qualquer corpo → exhausted
    - 429 com `error.details.error_code="enforced_spend_limit_reached"` → exhausted
    - 400 "You have reached your specified API usage limits" → exhausted
    - 401 → revoked
    - 429 com header retry-after: 12 → cooldown 12 s; sem header → cooldown 30 s
    - 500/529/504 → notKeyProblem; 400 de validação ("prefill") → notKeyProblem
    Transporte (fake Anthropic httptest + miniredis):
    - chave A responde credit-too-low, chave B responde 200 → cliente vê o 200 de B; header x-api-key de B enviado; Redis `gw:anthropic:key:<fpA>` com state exhausted e until = próximo dia 17 00:00 America/Sao_Paulo
    - requisição seguinte vai DIRETO para B (A não é chamada enquanto now < next_probe_at)
    - now avançado 6 h+1 min → A é tentada de novo primeiro; se 200 → Redis de A apagado (state ok)
    - chave sem dia (RenewalDay 0) esgotada → until = now + 6 h
    - todas esgotadas → RoundTrip retorna erro com errors.Is(err, errUpstreamRetryable) e SkipBreaker()=true, sem chamar o fake
    - 529 na chave A → resposta 529 devolvida como está (não troca chave; cascata é decisão do interceptor de status)
    - 429 rate_limit com retry-after 5 em A → A em cooldown 5 s, B atende
    - dia de renovação 31 em mês de 30 dias → clamp para o último dia do mês
    - Authorization do request removido; x-api-key e anthropic-version: 2023-06-01 presentes
    - body do request é reenviado idêntico em cada tentativa (GetBody ou buffer)
    - Redis indisponível (miniredis fechado) → pool continua em ordem fixa usando estado em memória, loga WARN uma vez
    - nenhuma linha de log capturada (slog handler em buffer) contém a string da chave
