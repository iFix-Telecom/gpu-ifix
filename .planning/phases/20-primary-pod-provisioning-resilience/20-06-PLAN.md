# Plan 20-06 — HUMAN-UAT: live coldstart fast-fail on real Vast (regimes 1 & 3)

Fast-fail is timing logic against real paid infra; the unit tests use the `budget=0` idiom
but CANNOT prove the loop kills a REAL pod at ~budget (not at the `coldstart_budget_s`
ceiling) nor that the Vast logs API (FF-03) actually surfaces the onstart heartbeat. This is
a blocking human-verify checkpoint. Budget: ~$1-2 of Vast spend, ~2-3 pod cycles.

**This plan also RESOLVES the two open questions the code deferred:**
- **Q2 — Vast logs API `result_url` shape:** capture the real `PUT /instances/request_logs/{id}/`
  response body + the `GET result_url` payload on the first live cycle; confirm the 20-03
  defensive decode matches, and tighten the JSON keys / add a result_url-host allowlist if
  needed.
- **Q3 — SSH-tail fallback:** decide from live evidence whether the Vast logs API is reliable
  enough to remain the SOLE progress source (leave SSH-tail deferred) OR whether it drops
  heartbeats badly enough to justify building the SSH-tail leg (follow-up quick-task).

**Pre-req:** the primary-pod image must include the OBS-11 heartbeat change (20-02) — rebuild
+ publish the pod image before this UAT, or the download will be silent and FF-02 cannot be
observed. Confirm the deployed gateway carries 20-04.

<threat_model>
Attack surface: this UAT spins REAL paid Vast pods and deliberately induces failures.
- **Billing-burn / orphans:** the whole point is to prove fast-fail SAVES money, but a UAT
  bug (or a `BestEffortDestroy` 429, per the STATE.md attempt-9 orphan that burned ~$2.17
  over 3.5h) could leave a paid instance running. Mitigation: after EACH cycle, the operator
  independently confirms 0 instances via the Vast UI/API (not just the gateway's view) and
  manually `curl DELETE`s any orphan; keep the session's cumulative spend visible.
- **Cred handling for the regime-3 stall:** breaking MinIO/R2 read creds to induce the stall
  must NOT leak a real secret into logs or the phase notes — use a scoped/temporary bad cred
  or an unreachable endpoint, not a redacted-real-key. The Vast API key + MinIO creds live in
  the pod env / gateway env, never pasted into the plan or VERIFICATION.
- **Blocklist pollution of prod picker:** auto-blocklisting during UAT writes REAL machine_ids
  into the live `pod_config.vast_machine_blocklist`, which the production picker reads. After
  UAT, review the blocklist and prune any machine parked purely by the induced-failure test
  (the blocklist has no auto-expiry yet — ponytail-marked). Record which machine_ids the UAT
  added so they can be pruned.
- **result_url SSRF surface:** capturing the live result_url confirms its host; if it is NOT
  a vast.ai / cloudflarestorage host, tighten the 20-03 GET to an allowlist before relying on
  FF-03 in prod.
</threat_model>
