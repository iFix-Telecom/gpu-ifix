# Plan 20-01 — CFG-01: two new pod_config budget fields end-to-end (migration 0033 + full stack)

Add `created_budget_s` (regime-1 fast-fail budget, FF-01) and `progress_stall_budget_s`
(regime-3 fast-fail budget, FF-02) to `ai_gateway.pod_config` as HOT owner-editable int
fields, each with min/max bounds — mirroring the EXISTING `coldstart_budget_s` /
`port_bind_budget_s` stack at every layer. This plan ONLY moves config plumbing; the
reconciler that READS these budgets is 20-04, the dashboard sliders are 20-05.

**Molde to copy verbatim (do NOT invent a new shape):** everything `coldstart_budget_s`
and `port_bind_budget_s` already do. They are `INTEGER NOT NULL` hot fields with
`_min`/`_max` `INTEGER NOT NULL` bound columns, a `writeIntConfig` PATCH case, two
`writeIntBoundMin/Max` bound cases, a `GetPodConfig` scan, a `SeedPodConfig` insert param,
a `podconfig.PodConfig`/`PodConfigBounds` field, a `config_read.go` response field, a seed
default in `podConfigSeedParams`, and a line in the UPDATE NOTIFY trigger WHEN-clause.

**Seed defaults (decision #6, mirror port_bind 120/30/600):** `created_budget_s`=120
(min 30, max 600), `progress_stall_budget_s`=120 (min 30, max 600).

**Open-question resolutions baked in:**
- Q5 (migration defaults): the migration `ADD COLUMN ... NOT NULL DEFAULT <n>` is
  LOAD-BEARING for the live prod row — `SeedPodConfig` is `ON CONFLICT DO NOTHING` so it
  will NOT populate the new columns on the already-seeded prod row. The SQL `DEFAULT`
  backfills existing rows; the seed param covers fresh installs. Both must be set.

<threat_model>
Attack surface: this plan adds two owner-editable numeric budgets that (in 20-04) gate how
long a paid Vast pod is allowed to burn before being destroyed.
- **Billing-burn via bad bounds:** an operator (or a bug) setting `created_budget_s_max`
  absurdly high, then `created_budget_s` to that max, would let a dead pod burn toward the
  `coldstart_budget_s` ceiling — defeating FF-01. Mitigation: seed `created_budget_s_max`=600
  (10 min hard ceiling on the new budget); the existing `coldstart_budget_s` remains the
  absolute ceiling regardless. The PATCH path already gates value-vs-bound server-side
  (Phase 17 D-03a) — reused, not bypassed.
- **Budget=0 footgun:** 20-04 uses `budget=0 fires on first poll` as a TEST idiom; a live
  `created_budget_s`=0 would kill every provision instantly. Mitigation: `created_budget_s_min`
  seeded at 30 blocks 0 from being saved via the dashboard/PATCH.
- **No secrets handled here** (pure config plumbing). Migration DEFAULT is the only
  server-side write; no untrusted input reaches SQL (sqlc parameterised).
- **NOTIFY trigger omission:** forgetting a new column in the WHEN-clause is silent — the
  edit saves but never hot-reloads. Guarded by the acceptance grep for all 6 columns.
</threat_model>
